**Key Features**

* Independent receiver (RX) and transmitter (TX)
* Fixed frame format: 8 data bits, no parity, and 1 stop bit (8N1)
* Software-configurable baud rate
* Independently configurable RX and TX FIFO depths
* Optional RTS/CTS hardware flow control
* Programmable RX and TX FIFO status interrupt conditions
* RX FIFO overflow indication
* RX start-bit and stop-bit validation


**Overview**

The NEORV32 UART provides an asynchronous serial interface with independent transmitter and receiver channels.
Each channel has a configurable FIFO. The frame format is fixed to **8N1**: one start bit, eight data bits, no
parity bit, and one stop bit.

The UART provides three memory-mapped registers:

* `CTRL`: control, status, and interrupt configuration
* `BAUD`: baud-rate configuration
* `DATA`: receive and transmit data

.C Standard Console
[NOTE]
All default example programs and software libraries of the NEORV32 software framework (including the bootloader
and the runtime environment) use the primary UART (UART0) as default user console interface. Furthermore, UART0
is used to implement C's `stdio` standard consoles `STDIN`, `STDOUT` and `STDERR`.


**Theory of Operation**

The receiver and transmitter are enabled independently using `UART_CTRL_RX_EN` and `UART_CTRL_TX_EN`. Clearing
either bit terminates the corresponding operation and clears its FIFO. The corresponding channel can no longer
trigger an while disabled. The baud rate is configured through the 10-bit (`baud_div`) and 3-bit clock prescaler
select (`clock_prescaler`) fields in the BAUD register.

.UART0 Clock Configuration
[cols="<4,^1,^1,^1,^1,^1,^1,^1,^1"]
[options="header",grid="rows"]
|=======================
| **`UART_CTRL_PRSC[2:0]`**   | `0b000` | `0b001` | `0b010` | `0b011` | `0b100` | `0b101` | `0b110` | `0b111`
| Resulting `clock_prescaler` |       2 |       4 |       8 |      64 |     128 |    1024 |    2048 |    4096
|=======================

****
_**Actual baud rate**_ = (_f~main~[Hz]_ / `clock_prescaler`) / (`baud_div` + 1)
****

The achievable baud rate is limited by the available prescalers and the 10-bit divisor. Select the configuration
according to the required baud-rate accuracy.

Writing `DATA` submits a byte to the TX FIFO. Before writing, software should check that `UART_CTRL_TX_FULL` is
clear. Reading `DATA` retrieves a byte from the RX FIFO; software should first check that `UART_CTRL_RX_EMPTY` is
clear. `UART_CTRL_TX_BUSY` remains set while the TX FIFO is not empty or the transmitter is active. Use this flag
when software needs to wait until a transmission has completed.

The FIFO depths are configured using the `IO_UART0_RX_FIFO` and `IO_UART0_TX_FIFO` generics. Software can determine
the configured depths from the `UART_CTRL_RX_FIFO` and `UART_CTRL_TX_FIFO` fields in `CTRL`.


**RTS/CTS Hardware Flow Control**

Hardware flow control uses the active-low CTSn input (`uart0_ctsn_i`) and RTSn output (`uart0_rtsn_o`). CTS and RTS
are enabled independently using `UART_CTRL_CTS_EN` and `UART_CTRL_RTS_EN`. When CTS flow control is enabled, the
transmitter waits for CTSn to be low before starting a new frame. When the receiver and RTS flow control are enabled,
RTSn is low while the RX FIFO is less than half full. RTSn becomes high when the FIFO is at least half full.
When RTS flow control is disabled, RTSn is low while the receiver is enabled. RTSn is high when the receiver is disabled.


**Error Checks**

The receiver validates the start and stop bits of each frame. If the sampled start bit is no longer low, reception is
aborted. If the sampled stop bit is not high, the received frame is discarded and is not written to the RX FIFO. The
UART does not provide a separate framing-error flag or per-byte error bits.

`UART_CTRL_RX_OVER` indicates that a write to a full RX FIFO occurred. The flag remains set while the FIFO remains
full and is cleared automatically when FIFO space becomes available or when the receiver is disabled.


**UART Interrupt**

The UART provides one combined CPU interrupt. RX and TX interrupt conditions are selected independently using the
two-bit `UART_CTRL_RX_IRQ_SEL` and `UART_CTRL_TX_IRQ_SEL` fields. The interrupt is level-sensitive: it remains asserted
while an enabled channel has a matching condition. The `UART_CTRL_RX_IRQ_PEND` and `UART_CTRL_TX_IRQ_PEND` flags report
the current selected conditions. The CPU interrupt is gated by the corresponding RX or TX enable bits.
An interrupt handler must remove the condition or disable the corresponding interrupt selection to prevent repeated
interrupts. In particular, a TX idle or TX not-full condition can be true immediately after configuration

.UART RX/TX Interrupt Trigger Select (and provided bit field C-macros)
[cols="^1,^6,^6"]
[options="header",grid="all"]
|=======================
| Value | Receiver (RX) | Transmitter (TX)
| `00` | `UART_RX_IRQ_NONE` : Interrupt disabled | `UART_TX_IRQ_NONE` : Interrupt disabled
| `01` | `UART_RX_IRQ_AVAIL` : Interrupt if FIFO is not empty (data available) | `UART_TX_IRQ_IDLE` : Interrupt if FIFO is empty and transmitter is idle
| `10` | `UART_RX_IRQ_HALF` : Interrupt if FIFO is at least half full | `UART_TX_IRQ_NHALF` : Interrupt if FIFO is less than half full
| `11` | `UART_RX_IRQ_FULL` : Interrupt if FIFO is full | `UART_TX_IRQ_NFULL` : Interrupt if FIFO is not full (free space available)
|=======================


**Simulation Mode**

TX simulation mode redirects writes to the simulator console instead of transmitting them through the physical
TX interface. Set `UART_CTRL_TX_SIM_EN` to enable this mode in simulation. The bit cannot be enabled in
synthesized hardware. In simulation mode, carriage returns are ignored and a line feed flushes the accumulated
output line to the simulator console.

**Overview**

The secondary UART (UART1) is functionally identical to the primary UART
(<<_primary_universal_asynchronous_receiver_and_transmitter_uart0>>). UART1
is mapped to a different base address and uses a different FIRQ channel.
