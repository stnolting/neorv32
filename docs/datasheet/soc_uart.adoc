==== Primary Universal Asynchronous Receiver and Transmitter (UART0)

|                         | `IO_UART0_RX_FIFO` | RX FIFO depth (power of 2, min 1)

**Key Features**

* Independent receiver (RX) and transmitter (TX)
* Fixed format: 8 data bits, 1 stop bit, no parity bit (8N1)
* Programmable baud rate
* Optional RX/TX FIFO buffer
* Optional RTS/CTS hardware flow-control
* Interrupt based on RX and TX FIFO status


**Overview**

The NEORV32 UART provides a standard universal asynchronous serial interface with independent transmitter and
receiver channels, each equipped with a configurable FIFO. The transmission frame is fixed to a **8-N-1** format:
8 data bits, no parity bit, and 1 stop bit. The actual transmission baud rate is programmable via software.
Optional RTS and CTS hardware flow control is also supported.

The modules provides three memory-mapped registers: A control and status register (`CTRL`), a register to
configure the tranmissionÄ's baud rate (`BAUD`) and a data register for reading receive data and sending
transmit data (`DATA`).

.C Standard Console
[NOTE]
All default example programs and software libraries of the NEORV32 software framework (including the bootloader
and the runtime environment) use the primary UART (UART0) as default user console interface. Furthermore, UART0
is used to implement C's `stdio` standard consoles `STDIN`, `STDOUT` and `STDERR`.


**Theory of Operation**

The receiver and transmitter channels are individually enabled by the `UART_CTRL_RX_EN` and `UART_CTRL_TX_EN`
control register flags. Clearing any of those flags will immediately terminate any receive/transmission operations
and will also clear the according RX/TX FIFO including any pending interrupts.

The transmission baud rate is configured by a 10-bit baud divisor (`baud_div`) and a 3-bit clock prescaler select
(`clock_prescaler`). Both values are programmed via the `BAUD` register.

.UART0 Clock Configuration
[cols="<4,^1,^1,^1,^1,^1,^1,^1,^1"]
[options="header",grid="rows"]
|=======================
| **`UART_CTRL_PRSC[2:0]`**   | `0b000` | `0b001` | `0b010` | `0b011` | `0b100` | `0b101` | `0b110` | `0b111`
| Resulting `clock_prescaler` |       2 |       4 |       8 |      64 |     128 |    1024 |    2048 |    4096
|=======================

****
_**Actual baud rate**_ = (_f~main~[Hz]_ / `clock_prescaler`) / (`baud_div` + 1)
****

A new TX transmission is triggered by writing to the `DATA` register. Vice versa, available RX data can be read
from the `DATA` register. The `DATA` register is transparently buffered by the configurable RX and TX FIFOs.
The control register provides flags to check the RX and TX FIFO status ("empty", "at least half full", and "full").
The FIFO sized are configured by the according top generics: `IO_UART0_RX_FIFO` and `IO_UART0_TX_FIFO`.
Software can determine the configured sizes via the `UART_CTRL_*X_FIFO` control register bits.


**RTS/CTS Hardware Flow Control**

Hardware flow control using the standard low-active CTSn (`uart0_ctsn_i`, "clear to send") and RTSn
(`uart0_rtsn_o`, "ready to send" / "ready to receive") can be enabled by the `UART_CTRL_CTS_EN` and
`UART_CTRL_RTS_EN` control register bit.

If `UART_CTRL_CTS_EN` is set, the transmitter will not start a new transmission until the `uart0_ctsn_i`
signal goes low. Vice versa, the receiver will keep `uart0_rtsn_o` low as long the RX FIFO is not at least
half empty if `UART_CTRL_RTS_EN` is set. `uart0_rtsn_o` is always low if CTS hardware flow-control is
disabled. It is always high if the receiver is entirely disabled.


**UART Interrupt**

The UART module provides a single interrupt that can be used to signal certain RX/TX (FIFO) conditions,
which are programmed individually for the receiver and the transmitter using the 2-bit `UART_CTRL_RX_IRQ_SEL`
and `UART_CTRL_TX_IRQ_SEL` control register bits. As soon as **any** programmed interrupt condition matches,
theCPU interrupt is triggered. The software can determine the actual cause of the interrupt using the
`UART_CTRL_RX_IRQ_PEND` and `UART_CTRL_TX_IRQ_PEND` flags.

.UART RX/TX Interrupt Trigger Select (and provided bit field C-macros)
[cols="^1,^6,^6"]
[options="header",grid="all"]
|=======================
| Value | Receiver (RX) | Transmitter (TX)
| `00` | `UART_RX_IRQ_NONE` : Interrupt disabled | `UART_TX_IRQ_NONE` : Interrupt disabled
| `01` | `UART_RX_IRQ_AVAIL` : Interrupt if FIFO is not empty (data available) | `UART_TX_IRQ_IDLE` : Interrupt if FIFO is empty and transmitter is idle
| `10` | `UART_RX_IRQ_HALF` : Interrupt if FIFO is at least half full | `UART_TX_IRQ_NHALF` : Interrupt if FIFO is less than half full
| `11` | `UART_RX_IRQ_FULL` : Interrupt if FIFO is full | `UART_TX_IRQ_NFULL` : Interrupt if FIFO is not full (free space available)
|=======================


**Simulation Mode**

Simulation mode allows to redirect TX data to the simulator console instead of sending it via the
physical `uart0_txd_o` line. Simulation mode is enabled by setting the `UART_CTRL_TX_SIM_EN` bit.

**Overview**

The secondary UART (UART1) is functionally identical to the primary UART
(<<_primary_universal_asynchronous_receiver_and_transmitter_uart0>>). UART1
is mapped to a different base address and uses a different FIRQ channel.
